# Grace Sun — Architecture Portfolio

## Concept

Grace Sun — Architecture Portfolio is a soft, atmospheric architecture portfolio designed primarily for graduate-school admissions reviewers. The website should feel creative, experimental, and architectural while keeping the projects themselves as the main focus.

The visual identity should be distinctive enough to be memorable, but restrained enough that it never competes with drawings, models, diagrams, renders, or project photography.

## References

No specific named website, architect, studio, or brand reference was provided.

The design system should instead borrow from three general reference directions:

1. Soft editorial architecture portfolios
- Borrow: asymmetrical but controlled composition, strong image hierarchy, elegant typography, and varied project scales.
- Do not copy: any specific layout, identity, logo, text, images, or fonts.

2. Atmospheric architectural presentation
- Borrow: translucent layers, soft shadows, light backgrounds, subtle material feeling, and calm transitions.
- The website should feel closer to an architectural presentation or exhibition than a commercial website.

3. Contemporary portfolio grid systems
- Borrow: an underlying grid that keeps the website organized while allowing important projects and images to occupy larger areas.
- Not every project card should have the same size or visual weight.

The goal is to borrow systems and principles only, never the identity of another designer or website.

## Mood

The website should feel:

- Creative
- Experimental
- Architectural

It should also remain soft, calm, and visually refined.

It must never feel:

- Corporate
- Childish
- Techy or science-fiction-like

It should also avoid looking like a generic portfolio template.

## Layout and Grid

Use a flexible 12-column desktop grid.

The layout should feel controlled but not rigid.

Important projects may:
- Span multiple columns
- Use larger images
- Break the normal card scale
- Receive more vertical space

Secondary projects can appear smaller.

Do not make every project card identical.

Desktop:
- Maximum content width around 1440px
- Outer margins should feel generous but not empty
- Use approximately 24px gutters

Tablet:
- Reduce to a 6-column system

Mobile:
- Use a simple 1-column or 2-column system depending on content

The underlying grid should create order while the image scale creates rhythm.

The website must not feel unfinished because of excessive white space.

## Image Treatment

Project images are the main visual content.

Use:
- Large architectural images
- Framed drawings
- Full-width images for important work
- Smaller diagrams grouped together
- Controlled image combinations

Image treatment can vary depending on the project.

Important images may appear large.

Supporting diagrams may appear smaller and aligned to the grid.

Avoid forcing every image into the same aspect ratio.

Do not apply strong filters that change the project itself.

Use soft transitions only.

## Movement

Movement should be subtle.

Allowed:
- Gentle fade-in when content enters the viewport
- Small image scale change on hover
- Soft colour changes
- Smooth scrolling
- Gentle link and button transitions

Avoid:
- Strong parallax
- Constant animation
- Large moving backgrounds
- Cursor-following effects
- Animation that delays access to project content

Animation should support navigation and hierarchy, not become the design itself.

## Home Page

The Home page should immediately communicate a strong design identity without emphasizing Grace Sun's name.

The first screen should prioritize:
- A strong architectural project image or composition
- The site title or a short portfolio statement
- A restrained navigation menu
- A visual introduction to selected work

Grace Sun's name should not dominate the hero section.

Projects should become visible quickly.

Avoid a long introduction before showing work.

## Log-In Page

The log-in page is the front door of the portfolio.

It should feel connected to the rest of the website rather than looking like a generic authentication screen.

Use:
- Warm off-white background
- One atmospheric architectural image or image placeholder
- A translucent or paper-like sign-up/log-in panel
- Large serif title
- Small DM Sans interface text
- Soft borders
- Minimal shadow

The page should clearly contain:

- Email field
- Password field
- Log in button
- Sign up option

The interface must remain simple and obvious.

Do not make the authentication interaction experimental or confusing.

## Navigation

Main navigation:

Home
About Me
Projects
Contact

Keep navigation visible and simple.

Desktop:
Use a horizontal navigation system near the top of the page.

Mobile:
Use a simple compact menu.

Every page should also contain a Log Out control.

Navigation must never require users to guess where content is located.

## Buttons

Buttons should be understated.

Primary button:
- Soft Black background
- Warm Off-White text

Secondary button:
- Transparent background
- Thin Soft Black border

Hover:
- Small colour or opacity change
- 150–250ms transition

Avoid:
- Large rounded app-style buttons
- Bright gradient buttons
- Glowing effects

## Tone of Voice

Text should be:

- Clear
- Concise
- Reflective
- Design-oriented
- Professional without sounding corporate

Project descriptions should explain ideas and design thinking without becoming long academic essays.

Use short paragraphs and clear captions.

## Five Never Rules

1. Never let visual effects compete with the architecture projects.

2. Never make the website look like a generic portfolio template.

3. Never use excessive animation, colour, or decorative effects.

4. Never give every project exactly the same size and visual importance.

5. Never sacrifice readability or navigation clarity for experimental design.
